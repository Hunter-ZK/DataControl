# DataControl｜功能入口与资产页操作｜二、三批交付说明

日期：2026-10-28（开发分支 `feature/r0-r1-harness-autonomy-20261027`，Draft PR #6）

## 目标与基线

在 PR #6 Atlas 蓝白风格和已存在的 Agent / 元数据路由上持续增量开发。三类入口保持：开放问题走对话，外部批量字段命名走工作台，已有资产操作留在详情页。未修改已确认词根索引样式。生产 SQL 不执行。大模型不得虚构治理词根或生产数据。

## 本次实际完成的代码

### 1. 字段完整性与反查准确性
- `GET /api/v1/tables/{asset_id}/columns/complete`：提供最多 5000 个字段的全量/计数一致契约；字段过大、表不存在或发生读取差异时失败关闭，不返回伪完整结果。
- 数据集 DDL 草案和字段字典改用该接口，不再将展示用的最多 500 行当作完整来源。
- 既有 `agent-assets/references` 反查接口已覆盖码表、标准、统计制度，本次补真实 `total`、截断状态、技术名，并允许上限 5000 条；前端做引用区块及可下载完整 CSV。不再声称需要重复新建三个反查接口。
- 数据集 DDL/SELECT 是带缺项说明的草案，不含未经确认的分区、生命周期和库方言。

### 2. 字段规范化命名工作台
- 新增 `/workbench/naming` 四步页面：输入→设置→逐行复核→导出，保持浅蓝白卡片及交替行背景。
- `/import` 读取上传的 XLSX / CSV（8 MiB、2000 行、80 列限制），也可粘贴每行字段中文名；导入的其他列在导出中保留。
- `/suggest` 严格使用平台注册词根和唯一已有字段名称，做可复现的确定性分词、规则组合与命名冲突标注。缺少词根只标记、不臆造缩写。默认 snake_case / 长度 64，仅为**试用规则**，不代表单位正式命名制度。
- 复核表支持手工编辑、行确认、批量确认可用条目、待确认与关注筛选；未知词根集中汇总。
- `/export` 下载两工作表 XLSX：命名结果、建议新增词根（未知英文缩写保持空白）；有电子表格公式注入转义。
- 新增登录用户独立的 `sys_naming_run` 运行记录表与 Alembic `20261028_0007` 迁移；可保存标题和当时的复核内容、列出最近 30 次、按原始数据重新下载、删除。不同账户的运行记录不能互相访问。
- 首页、导航栏、数据集页、词根页均有工作台入口。
- 当前没有接入模型分词或企业正式规则文件；不得把规则预览误当作经治理的正式命名结果。

### 3. Agent 资产侧边抽屉
- `AssetAgentDrawer.vue` 采用现有 Agent 服务端登录、会话、流式执行、停止接口和复用的 `AgentMessage` 回答组件，非虚构假进度。
- 绑定对象的资产类型、稳定 asset_id、技术名；支持继续追问及通过服务端会话 ID 在完整 Agent 页继续。
- 仅官方 DeepSeek 问数档用于内部数据资产；现有开放公共免费模型不接收内部资产内容。
- 完整会话沿用已有历史与权限检查，侧边抽屉不独立模拟聊天服务。服务不可用会明确提示。
- 此处基于已有的 Portal 登录验证，**不代表** Portal–MCP 的逐用户数据权限下传已完成，不能作为生产多租户权限隔离验收。

### 4. 资产引用与操作统一
- 数据集、字段、指标、码表、标准、词根和统计制度详情使用同一 `AssetOperationBar`，并在现有 ⌘K/Ctrl+K 面板中列出当前资产可执行操作。
- 码表、标准、统计制度的反查列表可跳转真实字段/指标，超过显示限制时提供明确截断提示，导出重新获取完整登记记录。
- 不展示空壳指标编译、未知代码审查能力。标准/制度导出及码值列表仍有 CSV 形式，未宣称全部 XLSX 已交付。

## 测试与边界

已有后端：`test_asset_operations.py`、`test_naming_workbench.py`、`test_naming_history.py`、迁移升级契约；前端 Vitest：`asset-exports.spec.ts`、`naming-review.spec.ts`；Playwright：`asset-workflows.spec.ts`，覆盖命名复核和资产 Agent 抽屉。本次开发修复了 GitHub CI 发现的 Python Ruff 导入错误、数据库迁移号断言及浏览器测试重复定位器。
