# Next-P1 验收清单

Next-P1 的验收对象是 `feature/next-p1-search-field-lineage`。P0 已冻结，不在本轮重新扩展范围。

本阶段产品目标：让资产“找得到、关系看得懂、字段可追溯”，并把统一检索与关系图谱的功能与视觉尽量对齐 DataControl V2 原型中的“统一检索 V2”和“关系图谱 V2”。

## 1. 启动与自动验收

首次切换到该分支后：

```bash
git checkout feature/next-p1-search-field-lineage
git pull origin feature/next-p1-search-field-lineage
bash ./scripts/stop-dev.sh
bash ./scripts/setup-dev.sh
bash ./scripts/start-dev.sh
```

Windows 对应使用 `stop-dev.ps1` / `setup-dev.ps1` / `start-dev.ps1`。

服务启动后执行：

```bash
./.venv/bin/python scripts/p1_acceptance.py
```

预期输出：

```text
NEXT-P1 LIVE API ACCEPTANCE PASSED
Manual UI acceptance remains required for Search V2 / Relation Graph V2 visual fidelity.
```

## 2. 统一检索 V2

打开“资产检索”。

### P1-SR-01 短词与多词

1. 搜索 `贷款`：必须返回结果，不能再出现 2 字中文零结果。
2. 搜索 `贷款 余额`：必须返回结果；顶部应显示被拆分的两个词以及真实总数。
3. 搜索结果中的命中词应高亮，技术名、中文名和业务定义均可参与召回。

### P1-SR-02 分面

1. 左侧显示资产类型、数仓层级、主题目录和状态。
2. 选择“指标”后，结果只显示指标；但资产类型分面仍保留其它类型的真实命中数，而不是全部变为 0。
3. 点击“清除”恢复全部筛选。

### P1-SR-03 最佳匹配与分页

1. 页面顶部应有“最佳匹配”卡片，不应只是一长串列表。
2. 普通结果区应有“全部/字段/指标/数据集/数据标准”等结果切换入口。
3. 每页 20 条，并显示“第 X–Y 条，共 N 条”。
4. 翻到后续页后结果应变化；不再固定只取前 60 条。

### P1-SR-04 Agent 联动

顶部绿色意图条应提供“问：……”入口。点击后进入“智能问数”，提问内容已经带入输入框；如果从具体数据集卡片进入，还应携带当前资产上下文。

## 3. 资产目录

打开“资产目录”。

1. 总数应覆盖完整合成语料，而不是最多 200 条。
2. 翻到第 13 页附近仍应存在数据集（当前验收语料为 260 张）。
3. 业务目录筛选和关键词查询由服务端执行，翻页后筛选条件保持一致。

## 4. 关系图谱 V2

打开“关系图谱”，默认中心资产使用 `DS000004`（地区贷款月度汇总）。

### P1-RL-01 资产选择器

1. 中心资产不是手填 Asset ID 的裸输入框，而是名称/表名搜索选择器。
2. 输入 `贷款合同`，应能选择贷款合同相关数据集（包括 `DS000001`）。

### P1-RL-02 有向图与遍历

1. 图上必须真正画出节点之间的连线与箭头。
2. 上游位于中心资产左侧，下游位于右侧，并按层级展开。
3. 切换“上游 / 下游 / 上下游”和 1–5 层后，图应重新计算。
4. `DS000004` 三层“上下游”不应混入 `DS000008`、`DS000009` 这类仅属于上游祖先其它下游分支的资产。

### P1-RL-03 证据与视觉

1. `CONFIRMED` 使用实线；`INFERRED` 使用虚线。
2. 可单独关闭“已确认”或“推断”关系。
3. ODS / DWD / DWS / ADS / DIM 使用独立层级色标签。
4. 支持缩小、复位、放大；中心资产有明显当前态。

### P1-RL-04 影响与路径

1. 右侧“下游影响”显示影响数据集与关系数量，并列出部分下游资产。
2. “导出影响清单 CSV”可下载当前影响数据集清单。
3. 路径查询使用目标资产搜索器；例如从 `DS000001` 查到 `DS000006` 应存在路径。
4. 路径结果应显示每一跳对应的 ETL/task 名称，并在图中高亮对应边。

## 5. 字段级血缘

在关系页切换“字段血缘”，或从任意字段详情点击“查看字段血缘”。

1. 通过字段中文名或技术名搜索中心字段。
2. 图中展示字段的上游与下游节点，而不是只展示表级关系。
3. 右侧“字段变换”展示 `DIRECT / AGGREGATED / DERIVED`、转换表达式、任务名和证据状态。
4. `DS000004.loan_balance` 应存在上游关系；聚合场景应能看到类似 `SUM(loan_balance)` 的转换事实。
5. 字段详情页必须存在“查看字段血缘”入口。

## 6. UI 对照重点

人工验收时重点和 Claude V2 原型对照以下视觉结构：

- 统一检索：大搜索框、检索词提示、Agent 意图条、左侧分面、双“最佳匹配”卡、结果 tabs、分页。
- 关系图谱：单行控制条、中心资产搜索选择器、真实有向图、右侧影响卡、右侧路径卡、证据图例。
- 整体保持 Light Ocean：浅海蓝背景、白色卡片、蓝绿色主交互色、低饱和层级色、技术名等宽字体。

原型是视觉和交互基线，不允许为了“看起来一样”写死命中数、可信状态或关系数量；页面数字、关系证据和状态必须来自真实 API。

## 7. 通过标准

P1 只有同时满足以下条件才可冻结：

- GitHub Actions 全矩阵绿色；
- `scripts/p1_acceptance.py` 通过；
- 上述检索、目录、表级关系、字段级关系均通过人工功能验收；
- Search V2 / Relation Graph V2 的视觉结构无明显偏离原型；
- 未发现 P0 可信 SQL / Agent 能力回归。

用户验收前，不合并 PR #4，也不进入 Next-P2。
