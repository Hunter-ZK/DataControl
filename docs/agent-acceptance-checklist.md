# DataControl Agent R0 验收清单（Windows，本地开发环境）

适用分支：`feature/r0-r1-harness-autonomy-20261027`。本清单只验收当前已经开发的功能，不以尚未开发的 R1 流式输出、全资产检索或多步骤生产数仓开发能力作通过条件。

## 0. 准备工作（首次一次）

在仓库根目录的 PowerShell 中执行：

```powershell
git fetch origin
git switch feature/r0-r1-harness-autonomy-20261027
git pull --ff-only
.\scripts\setup-dev.ps1
.\scripts\setup-agent.ps1
```

把 DeepSeek API Key 设置在**本地进程环境**（不要写入仓库，也不要把密钥截图或发到聊天中），然后启动：

```powershell
$env:DEEPSEEK_API_KEY = "你的实际密钥"
.\scripts\start-dev.ps1
```

打开 `http://127.0.0.1:5173`，选择【智能问数】页面。如果服务显示“未就绪”，先检查 API Key、端口 8000/8900/8910，以及 `.local/agent-gateway.err.log`。

## 2. 命令行验收（真实模型）

前端服务仍保持运行，在**第二个 PowerShell**、仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\p3_agent_acceptance.py
```

成功标志：终端出现 `LOCAL REAL-MODEL ACCEPTANCE PASSED`，并写出 `.local/p3-agent-acceptance.json`。该测试会消耗真实 API Token，也可能因模型输出不稳定而失败；**不能用 CI 桩模型成功代替**。

## 3. 查看实时 Agent 调用日志

原来的 `start-dev.ps1` 会将 Gateway 日志写入文件而非直接混到 Vite 终端。打开**第三个 PowerShell**、仓库根目录执行：

```powershell
Get-Content .\.local\agent-gateway.err.log -Tail 40 -Wait
```

保持这个窗口打开，再在网页中提问。日志按请求 ID 展示 START / TOOL_START / TOOL_END / DONE 或 ERROR，不展示问题全文、工具参数、SQL 正文、模型思维内容和密钥。

如要看 MCP 服务的底层日志：`Get-Content .\.local\agent-mcp.err.log -Tail 40 -Wait`。浏览器 F12 Console 是网页侧诊断，不是 Gateway 原生工具流记录。
