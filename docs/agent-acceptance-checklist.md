# DataControl Agent R0 验收清单（Windows，本地开发环境）

适用分支：`feature/r0-r1-harness-autonomy-20261027`。本清单覆盖 R0 原有能力及 R1-A 实时进度/停止。后续 R1 数据库会话存储、R2 全资产检索与 R5 多步骤数仓开发暂不作为通过条件。

## 0. 准备工作（首次一次）

在仓库根目录的 PowerShell 中执行：

```powershell
git fetch origin
git switch feature/r0-r1-harness-autonomy-20261027
git pull --ff-only
.\scripts\setup-dev.ps1
.\scripts\setup-agent.ps1
```

把 DeepSeek API Key 设置在**本地进程环境**（不要写入仓库，也不要把密钥截图或发到聊天中），然后启动：

```powershell
$env:DEEPSEEK_API_KEY = "你的实际密钥"
.\scripts\start-dev.ps1
```

打开 `http://127.0.0.1:5173`，选择【智能问数】页面。如果服务显示“未就绪”，先检查 API Key、端口 8000/8900/8910，以及 `.local/agent-gateway.err.log`。

## 1. 逐项手工验收

| ID | 在页面上怎么操作 | 预期现象 | 结果 |
| --- | --- | --- | --- |

**验收口径：** 当前真实 API 的结果来自模拟元数据；无真实业务数值输出是设计约束，不能因未得到真实金额将 A02 判为失败。工具是否真正被调用，以 UI 调用记录和 Gateway 日志为依据，不以文字“我已经调用”作为证据。

## 2. 命令行验收（真实模型）

前端服务仍保持运行，在**第二个 PowerShell**、仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\p3_agent_acceptance.py
```

成功标志：终端出现 `LOCAL REAL-MODEL ACCEPTANCE PASSED`，并写出 `.local/p3-agent-acceptance.json`。该测试会消耗真实 API Token，也可能因模型输出不稳定而失败；**不能用 CI 桩模型成功代替**。

## 3. 查看实时 Agent 调用日志

原来的 `start-dev.ps1` 会将 Gateway 日志写入文件而非直接混到 Vite 终端。打开**第三个 PowerShell**、仓库根目录执行：

```powershell
Get-Content .\.local\agent-gateway.err.log -Tail 40 -Wait
```

保持这个窗口打开，再在网页中提问。日志按请求 ID 展示 START / TOOL_START / TOOL_END / DONE 或 ERROR，不展示问题全文、工具参数、SQL 正文、模型思维内容和密钥。

如要看 MCP 服务的底层日志：`Get-Content .\.local\agent-mcp.err.log -Tail 40 -Wait`。浏览器按 **F12 → Console** 也能查看本轮工具调用摘要（回答完成后一次显示）；实时逐步日志以 Gateway 终端为准。两种方式均不输出问题全文、SQL 或工具参数。

## 4. R1-A 实时进度与停止验收

在页面操作即可，均不要求执行生产 SQL：

| ID | 操作 | 预期 |
| --- | --- | --- |
| R1A-01 | 输入“本期贷款余额，生成 SQL 并进行静态校验”，发送 | 提交后出现“DataAgent 正在分析”；后续仅在真实工具调用时显示解析指标、读取表结构、编译查询、静态校验等步骤，不伪造进度 |
| R1A-02 | 在仍执行的任务上点击“停止” | 前端退出等待态，当前答案不标记成功，不出现伪造 SQL；Gateway 日志出现 CANCELLED，运行中的 Harness 子进程终止 |
| R1A-03 | 在停止后再次提交问题 | 可以重新提问；不会错误延续已停止的、可能不完整的 Harness 上下文 |
| R1A-04 | 不点击停止，完成一次正常提问 | 显示最终答案、证据、SQL 与校验状态，流程与 R0 保持一致 |
| R1A-05 | 展开浏览器 F12 网络面板观察 `/api/v1/agent/query/stream` | 响应是逐行 NDJSON，只有 started、脱敏 activity、result 或取消/错误事件；没有隐藏思维、密钥、工具原始参数 |

提示：`started` 是请求已进入 Gateway 的信号，不代表大模型已经完成推理。是否有工具步骤取决于真实 Harness 行为。如果模型未调用工具，不应人为补出工具步骤。

## R1-B 本地验收（服务端历史）

先在根目录执行 `start.bat`，确认普通启动自动应用 Alembic 0005。使用两个不同的模拟测试账号，并准备一段原本留在当前浏览器 localStorage 的旧聊天记录。

| 编号 | 验收操作 | 必须观察到的结果 |
| --- | --- | --- |
| R1B-01 | 登录 A 发起一轮 SQL 问答，完成后刷新 | 历史来自服务端；问题原文、答案、SQL、验证结果、模式一致 |
| R1B-02 | A 同时打开两个标签页，向同一会话并行发起不同请求 | 只允许一轮运行，另一轮明确拒绝，不重复生成两份任务 |
| R1B-03 | 同一 runId 重复提交已完成请求 | 只回放已有终结结果，不重新调用 dsh |
| R1B-04 | 正常进行中点击停止 | 取消请求与最后 cancelled 分开；不出现“已停止”的伪成功 |
| R1B-05 | 强制断开数据流/刷新再重开 | 非最终完成任务显示失败或中断，无伪答案、不续接不完整会话 |
| R1B-06 | A/B 两用户访问彼此会话、runId | 返回 404/401，不披露其他用户历史或审计 |
| R1B-07 | 旧浏览器历史弹窗选择不导入/确认导入 | 不导入不丢数据；导入仅一次且模型模式正确 |
| R1B-08 | 未登录使用原智能问数 | 仍可用本地历史，服务端不创建无用户归属的会话 |
| R1B-09 | 免费测试与官方模型之间切换/恢复 | 不串用 provider session，第三方公共网关有确认提示 |

结果分为：代码已提交、自动化通过、Windows 本地通过、真实模型通过；四种状态不可混写。
