核对日期：2026-10-28
核对依据：已确认 Claude 方案、当前开发分支源码与本仓交付记录。
当前分支：`feature/r0-r1-harness-autonomy-20261027`（PR #6 Draft，尚未合并）。

## 总体结论

四轮 F1–F4 均已有功能代码，尚未达到各轮约定的完整验收门槛。
按原方案工作项的覆盖面粗估：约六成已具备实现，剩余约四成属于
**部分实现、工程化收口或尚未验收**；不是 CI 通过率，也不是模型准确率。
具体状况应以下面逐项核对为准。

### F1 收口与地基 —— 部分完成

已落地：
- Portal 登录检查、服务端会话归属／续接、取消与运行状态持久化、脱敏工具事件。
- 标准／多步两套独立 Harness Profile，默认不同超时档位。
- `agent/tool-catalog.json` 集中工具清单；`agent/.dsh/skills/` 共有 12 份 Skill。
- Gateway 真实 NDJSON 活动事件、Stub 契约测试与真实问题题库执行入口。
- 设计令牌、公共组件、Vue 文件拆分（Agent 页仍较大）。

尚缺：
- Claude 提出的第三档“快速模式”尚未形成独立档位。
- 标准档的 Goal/Todo/Subagent/Workflow 插件与 Skill 加载边界尚未完全做到严格技术隔离；
  目前以 Profile 配置及 prompt 为主，不等同于能力白名单。
- 工具目录当前为 **20 项**；原方案“保留 11＋新增 10”的目标为 21 项，需对照需求明确缺失能力而非机械补数。
- 真实 DeepSeek 基线与逐题验收未完成；自动化 CI 无法代替。
- 未完成全站无 12px 以下字体、全局样式无硬编码颜色、`prototype` 清理和严格依赖锁核验。
- `storage_bytes` / `row_count` 当前仍为 SQLAlchemy Integer，而不是方案中的 BigInteger。
- MCP 仍使用开发环境固定 PoC AuthzContext，未实现逐用户权限下传。

### F2 找数与可信 SQL —— 部分完成

已落地：
- `search_assets`、`get_asset`、`find_references`、`get_lineage_summary`、`revise_query`，
  及七类资产的 Portal 只读事实接口。
- 依据真实返回的 `assetId/assetType` 建立引用卡、资产跳转，结构化查询改写有基础守护。
- 首页单输入框明确区分“检索资产／问 DataAgent”，联想与结果卡、顶栏 ⌘K / Ctrl+K。
- 常用 SQL 检索与指标语义基础工具可调用。

尚缺：
- `MAX_PT` 以及受治理维表 JOIN 的完整确定性 SQL 编译规则；
  多指标／跨口径／同比环比等复杂问数覆盖率需进一步验证。
- 正式第二模型供应方及“快速≤1秒”实测门槛；公共免费模型不等于经过批准的正式第二供应方。
- 检索回表批处理、同义词/词根、FTS 性能及大规模真实数据基准尚未完成闭环。
- 歧义题是否全部能出现可操作澄清卡，尚缺全题库实测与评分。

### F3 过程与会话体验 —— 部分完成

已落地：
- 三栏问数界面、实际工具活动、证据／SQL 校验／工具步骤检查器。
- 服务端会话历史、取消、续接、固定任务档位；复制、重新生成、推荐追问、浏览器本地反馈。
- 实际耗时（毫秒）和工具调用次数记录。

尚缺：
- 运行级真实 Token 用量、成本计算与 P50/P95 基线。
- Guard 集中审计与更严格的运行策略；会话跨进程可靠续跑及持久任务执行。
- 明确的四层标准回答结构、任务计划标题和可操作任务拆解尚未完整产品化。
- 用户反馈持久化到服务端尚未完成。
- A01–A10 真人工验收、首次工具反馈≤1秒、所有回答资产可点击仍需逐项验收。

### F4 数仓开发辅助与体验完成度 —— 部分完成

已落地：
- `check_naming` / `generate_ddl` / `generate_etl` / `generate_dq_checks`；
  字段类型／已有字段／规则约束检查，默认只生成 `execution_allowed=false` 的草案。
- 对应 Skills、工具契约测试、Playwright 浏览器回归入口与宽屏／窄屏截图。
- 蓝白设计令牌、语义化资产图标、侧栏折叠、资产目录、检索和数据集标准／码表速览抽屉。

尚缺：
- 受治理的复杂数据仓库开发规划、DDL/DML 确认流程、跨任务产物追踪与业务级质量检验。
- 真实模型生成 SQL 的 DuckDB Golden 结果集对照和跨场景稳定性评测。
- Pinia 状态管理、自动 OpenAPI 类型生成、全部页面统一模板、全量移动端视觉和体验验收。
- 隔离的模拟 SQL 执行沙箱仍待明确独立授权，不应擅自开启生产执行。

## 六项优化现状

1. **身份、Session、安全**：Portal 会话归属已落地；MCP 动态用户授权未完成。
2. **结构化事实／资产证据**：主要工具与卡片已落地；覆盖与证据闭环需验证。
3. **QueryIR／SQL 改写**：已有结构化改写工具；复杂组合与语义稳定性未完成。
4. **统一入口与用户意图**：首页双动作、搜索与 Agent 导航已落地；完整多意图路由仍待完善。
5. **三层评测（静态、DuckDB、真实模型）**：静态及 Stub 有代码；结果集 Golden 比对和正式实测指标未完成。
6. **前端增量重构**：主要视觉与组件有成果；Pinia/OpenAPI/Stylelint/响应式全面验收仍缺。

## 建议下个开发批次

优先处理 F1 运行边界与方案必选修正（动态授权、BigInteger 迁移、
工具加载与固定 Profile），并建立真实 DeepSeek 题库基线；
其后补齐 F2 MAX_PT/维表及 F3 Token 审计；最后完成 F4 工作流与
前端工程治理。不要用不断新增图标来替代可信 SQL 质量验证。

新增的 `dsh-our-free-model` 已调整为**默认可选、自动安装**，
但发送仍以用户在界面选择公共模型为前提，且仅可使用公开模拟数据。
公开插件与固定 dsh 的版本兼容性待本地验证。
